## Reparación aplicada

El formulario podía indicar éxito con `DEV_EMAIL` aunque no hubiera entregado
correo. Tampoco incluía asunto ni conservaba el email del visitante en `Reply-To`.
Ahora incluye asunto, conserva los párrafos, valida los campos en cliente y
servidor, rechaza cabeceras inyectadas y aplica honeypot y cinco consultas por IP
y minuto. Un bloqueo síncrono evita dos envíos con un doble clic.

El buzón publicado, el destinatario y las opciones de servicio comparten
`backend-rust/src/contact-defaults.json`. `CONTACT_RECIPIENT_EMAIL` permite
configurar una única dirección utilizada también al construir el frontend.

Por autorización expresa del usuario, el backend utiliza la API oficial de
Postmark cuando existe su secreto de runtime. `POSTMARK_FROM` debe ser una
dirección corporativa autorizada; `From` nunca toma el email del visitante.
`To` utiliza el buzón publicado y `ReplyTo` utiliza el email validado del cliente.
Se comprueban HTTP, `ErrorCode`, destinatario y un `MessageID` válido antes de
devolver éxito. No se siguen redirecciones ni se acepta `POSTMARK_API_TEST`
como acreditación de entrega. Las respuestas de error no incluyen información
del proveedor ni credenciales.

La alternativa SMTP corporativa usa credenciales y TLS independientes de los
automatismos de autenticación. No se recurre a ella cuando un token Postmark
configurado produce un error. `DEV_EMAIL` no simula éxito en ninguno de estos
canales.

## Configuración y secreto

La API de servidor de Postmark respondió HTTP 200, en modo `Live`, tanto desde
el host como desde la red del backend. El token proporcionado permanece en
`.secrets/postmark_server_token`, excluido de Git y montado únicamente en runtime
del backend. No se incorpora como argumento de build ni al frontend.
Se comprobó su ausencia en la imagen, entorno público, API pública y logs.

No existe `POSTMARK_FROM` configurado ni remitente corporativo guardado en los
ajustes SMTP de la base principal. No se ha proporcionado API de cuenta ni
acceso autorizado al panel que permita confirmar un remitente. El usuario
confirmó que tampoco dispone actualmente de acceso autorizado al buzón para
comprobar recepción y destinatario al pulsar «Responder».

`POSTMARK_FROM` permanece vacío. No se ha enviado ningún mensaje real ni se ha
sustituido el remitente por una dirección cuya autorización se desconoce.
